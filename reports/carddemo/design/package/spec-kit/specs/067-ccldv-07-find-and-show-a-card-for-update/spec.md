# Feature specification: Find and show a card for update

**Feature:** CCLDV-C07 · Credit Card List Detail View and Update · Customer Data Setup

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (CCLDV-C07)

As a card operations user, I want to enter an account number and card number, or arrive with a card selected from the card list, and see that card's stored details, so that I can review the card before changing it.

Lets card operations staff find a card for update, either by entering an account and card number or by arriving with a card picked in the card list, and shows its stored embossed name, status and expiry. The values read at this point are kept as the card's original details, which later saves are checked against. It must reject missing or invalid keys with the exact messages and must report a card that is not found or a card file that cannot be read.

**Acceptance scenarios:**

## Requirements

### Functional requirements

- **CCLDV-REQ-F-061** (formatting): When the card update screen is started with no conversation data, or is entered from the main menu ('COMEN01C') as a fresh entry, the system shall clear the update state, show an empty search screen with 'Please enter Account and Card Number', and wait for the account and card number. Rules: CCLDV-BR-061, CCLDV-BR-062.
- **CCLDV-REQ-F-062** (formatting): When the card update screen is shown on a first entry (from the menu, or after an update completes or fails), the system shall show no search keys and no card details. Rules: CCLDV-BR-063.
- **CCLDV-REQ-F-063** (formatting): While card details have not yet been fetched, the system shall show the information message 'Please enter Account and Card Number' and show the embossed name, active status and expiry day, month and year as empty when the user returns to the card update screen. Rules: CCLDV-BR-064, CCLDV-BR-065.
- **CCLDV-REQ-F-064** (formatting): When the card update screen is redisplayed (not a first entry), the system shall show the account number and card number search keys, leaving each one blank when its value is zero. Rules: CCLDV-BR-066.
- **CCLDV-REQ-F-065** (design note): When the operator submits the screen with the account number or card number entered as '*' or left blank, the system shall treat that search key as not supplied, and otherwise shall take the entered value as both the search key and the new account number or card number. Rules: CCLDV-BR-067, CCLDV-BR-068.
- **CCLDV-REQ-F-066** (business rule): While no card has been fetched, the system shall validate only the account number and card number search keys, discard any card name, status or expiry entered, and skip all card-detail edits. Rules: CCLDV-BR-069, CCLDV-BR-070.
- **CCLDV-REQ-F-067** (business rule): If no card has been fetched yet and both the account number and the card number are left blank (or zero), then the system shall report 'No input received'. Rules: CCLDV-BR-071, CCLDV-BR-069.
- **CCLDV-REQ-F-068** (business rule): If no card is yet fetched and the account number entered is blank, '*' or all zeros, then the system shall flag an input error and show 'Account number not provided', unless an earlier message is already set. Rules: CCLDV-BR-072, CCLDV-BR-073.
- **CCLDV-REQ-F-069** (business rule): If no card is yet fetched and the account number entered is not numeric, then the system shall flag an input error and show 'ACCOUNT FILTER,IF SUPPLIED MUST BE A 11 DIGIT NUMBER', unless an earlier message is already set. Rules: CCLDV-BR-074, CCLDV-BR-073.
- **CCLDV-REQ-F-070** (business rule): If no card is yet fetched and the card number entered is blank, '*' or all zeros, then the system shall flag an input error and show 'Card number not provided', unless an earlier message, such as an account error, is already set. Rules: CCLDV-BR-075, CCLDV-BR-073.
- **CCLDV-REQ-F-071** (business rule): If no card is yet fetched and the card number entered is not numeric, then the system shall flag an input error and show 'CARD ID FILTER,IF SUPPLIED MUST BE A 16 DIGIT NUMBER', unless an earlier message is already set. Rules: CCLDV-BR-076, CCLDV-BR-073.
- **CCLDV-REQ-F-072** (business rule): When card details have not yet been fetched and the operator submits an account number and card number that both pass validation, the system shall read the card file ('CARDDAT') by card number alone and, if the card is found, show its details for editing with 'Details of selected card shown above' (state 'S'). Rules: CCLDV-BR-077, CCLDV-BR-078, CCLDV-BR-074, CCLDV-BR-076.
- **CCLDV-REQ-F-073** (business rule): If the card number is not on the card file, then the system shall flag both search keys as in error, show 'Did not find cards for this search condition' (unless an earlier message is already set), and keep the search screen. Rules: CCLDV-BR-079, CCLDV-BR-077.
- **CCLDV-REQ-F-074** (error handling): If the card file read fails for any other reason, then the system shall flag an input error and show 'File Error: READ on CARDDAT returned RESP <code>' with the response codes. Rules: CCLDV-BR-080.
- **CCLDV-REQ-F-075** (design note): When the requested card is found on the card file, the system shall keep as the card's original details the embossed name converted to upper case, the expiry year, month and day taken from the stored expiry date (positions 1-4, 6-7 and 9-10), the active status and the CVV code. Rules: CCLDV-BR-081.
- **CCLDV-REQ-F-076** (formatting): While the card details have just been fetched and are being shown unchanged (state 'S'), the system shall show, on redisplay, the card's stored embossed name, active status, expiry day, expiry month and expiry year as read from the card file, with the information message 'Details of selected card shown above'. Rules: CCLDV-BR-082, CCLDV-BR-083.
- **CCLDV-REQ-F-077** (business rule): When the operator arrives at card update from the card list ('COCRDLIC') for the first time, or presses PF12 while the card list is the calling program, the system shall take the account and card number passed by the card list, read that card, mark the details as shown and display the update screen. Rules: CCLDV-BR-084.
