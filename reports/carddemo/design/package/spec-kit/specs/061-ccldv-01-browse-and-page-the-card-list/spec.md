# Feature specification: Browse and page the card list

**Feature:** CCLDV-C01 · Credit Card List Detail View and Update · Customer Data Setup

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (CCLDV-C01)

As a card operations user, I want to see the credit cards seven at a time and page forward and back through them, so that I can find the card I need to view or update.

Card operations users browse the credit cards seven to a page and move forward and back through the list to find the card they want to view or update. Each row shows the card number, account number and active status. The list must never skip or repeat cards between pages, must say when there are no more pages, and must start again from the first card whenever the user comes in from the menu or returns from card detail or card update.

**Acceptance scenarios:**

1. **Given** menu option: 3 'Credit Card List', **when** the card list is started from the main menu, **then** Page 1 shows the first 7 cards in card-number order. (CCLDV-C01-AC-01)
2. **Given** coming from: COMEN01C; context: enter, **when** the card list is started from another program with context 'enter' (from main menu option 3, or on return from card detail or card update), **then** Paging starts afresh at page 1; nothing typed on an earlier list screen is used. (CCLDV-C01-AC-02)
3. **Given** previous program: COCRDSLC; key pressed: PF3; list page before leaving: 3, **when** the user arrives with PF3 from another program (such as leaving card detail or card update), or the list is re-entered from another program, **then** The list is shown again from page 1, not page 3. (CCLDV-C01-AC-03)
4. **Given** account filter: 00000000011; card read: 4111000000000008, account 00000000011, status 'Y', **when** the card list fills a page going forward, WHEN a card record passes the account and card-number filters, **then** The card is added as the next row, showing account 00000000011 and status 'Y'. (CCLDV-C01-AC-04)
5. **Given** account filter: 00000000011; card read: 4111000000000016, account 00000000022, **when** the card list fills a page going forward, WHEN a card record passes the account and card-number filters, **then** The card is skipped and no row is added. (CCLDV-C01-AC-05)
6. **Given** matching cards: 12; page: 1, **when** a page reaches 7 cards, **then** 7 cards are shown, and the 8th card is read ahead but not shown. (CCLDV-C01-AC-06)
7. **Given** cards in file after the 7th shown: 5, **when** the look-ahead read after a full page finds another card record, **then** The next page indicator is 'Y', so PF8 can be used. (CCLDV-C01-AC-07)
8. **Given** cards remaining from page start: 7, **when** a page is filled with the maximum of 7 cards and reading one card further reaches the end of the card file, **then** 7 cards are listed, no next page, message 'NO MORE RECORDS TO SHOW'. (CCLDV-C01-AC-08)
9. **Given** cards remaining from page start: 8, **when** a page is filled with the maximum of 7 cards and reading one card further reaches the end of the card file, **then** 7 cards are listed and PF8 will move to a next page. (CCLDV-C01-AC-09)
10. **Given** matching cards: 7; cards in file after the 7th: 0, **when** the forward read reaches the end of the card file, either while filling the page or on the look-ahead read, **then** 7 cards are shown, there is no next page, and the message is 'NO MORE RECORDS TO SHOW'. (CCLDV-C01-AC-10)
11. **Given** matching cards from page start: 3, **when** the end of the card file is reached before the page holds 7 cards, **then** 3 cards listed, no next page, 'NO MORE RECORDS TO SHOW'. (CCLDV-C01-AC-11)
12. **Given** page: 1; matching cards: 0, **when** the end of the card file is reached on page 1 with no card listed, **then** 'NO RECORDS FOUND FOR THIS SEARCH CONDITION.' is shown. (CCLDV-C01-AC-12)
13. **Given** key pressed: PF8; current page: 1; next page indicator: 'Y'; card found by the look-ahead read: 4111000000000081, **when** there is no input error and the user presses PF8 while a next page exists ('Y'), **then** Page 2 is shown, and its first card is 4111000000000081 or the next card after it that passes the filters. (CCLDV-C01-AC-13)
14. **Given** page: 2, first card 4111000000000008; key pressed: Enter; selection: none, **when** there is no input error, exit, page change or valid selection (for example Enter with nothing selected, or PF8 with no next page), **then** Page 2 is shown again starting at card 4111000000000008. (CCLDV-C01-AC-14)
15. **Given** key pressed: PF7; current page: 1, **when** there is no input error and the user presses PF7 while on page 1, **then** Page 1 is shown again with the message 'NO PREVIOUS PAGES TO DISPLAY'. (CCLDV-C01-AC-15)
16. **Given** page: 1; key pressed: PF7, **when** the user presses PF7 while on the first page and no filter is in error, **then** Message 'NO PREVIOUS PAGES TO DISPLAY' is shown. (CCLDV-C01-AC-16)
17. **Given** key pressed: PF7; current page: 2; first card on page: 4111000000000008, **when** there is no input error and the user presses PF7 while not on page 1, **then** Page 1 is shown with the cards before 4111000000000008, not including 4111000000000008 itself. (CCLDV-C01-AC-17)
18. **Given** matching cards before the current page: C1 to C9, in key order, **when** reading backward, **then** Rows 1 to 7 show C3 to C9, and C3 becomes the first card of the page. (CCLDV-C01-AC-18)
19. **Given** action: PF7 from page 3, whose first card is 4111000000000099, then PF8, **when** the user pages backward, **then** Page 3 is shown again, starting at 4111000000000099. (CCLDV-C01-AC-19)
20. **Given** page: last page, no next page; key pressed: PF8; last page already shown: no, **when** the user presses PF8 on the last page for the first time, **then** Same page is shown with 'TYPE S FOR DETAIL, U TO UPDATE ANY RECORD'; the last page is now marked as shown. (CCLDV-C01-AC-20)
21. **Given** page: last page, no next page; key pressed: PF8 (second time in a row), **when** the user presses PF8 again on a last page that has already been shown, **then** Message 'NO MORE PAGES TO DISPLAY' is shown. (CCLDV-C01-AC-21)
22. **Given** account filter: 12AB, **when** the account or card filter entered is invalid, **then** Only 'ACCOUNT FILTER,IF SUPPLIED MUST BE A 11 DIGIT NUMBER' is shown, no instruction. (CCLDV-C01-AC-22)
23. **Given** key pressed: Enter; cards found: 7, **when** the account or card filter entered is invalid, **then** Instruction 'TYPE S FOR DETAIL, U TO UPDATE ANY RECORD' is shown. (CCLDV-C01-AC-23)
24. **Given** page: 1; cards matching filter: 0, **when** the account or card filter entered is invalid, **then** 'NO RECORDS FOUND FOR THIS SEARCH CONDITION.' is shown without the instruction. (CCLDV-C01-AC-24)
25. **Given** key pressed: PF3; CDEMO-FROM-PROGRAM: 'COCRDLIC', **when** the user presses PF3 and the originating program is the card list, **then** Control transfers (XCTL) to 'COMEN01C' with the shared commarea, from-transaction 'CCLI'; the card list ends and the main menu is shown. (CCLDV-C01-AC-25)
26. **Given** key pressed: PF3; CDEMO-FROM-PROGRAM: 'COMEN01C' (first entry from the menu), **when** the user presses PF3 and the originating program is the card list, **then** No exit; the card list is shown. (CCLDV-C01-AC-26)
27. **Given** key pressed: ENTER; CDEMO-FROM-PROGRAM: 'COCRDLIC', **when** the user presses PF3 and the originating program is the card list, **then** User stays on the card list; the list is refreshed for the current filter. (CCLDV-C01-AC-27)
28. **Given** the user has pressed PF8 on the last page, so the list has recorded that the last page has been shown, **when** the user presses any key other than PF8, for example Enter or PF7, **then** the last-page flag is reset to 'not shown' (CCLDV-C01-AC-28)

## Requirements

### Functional requirements

- **CCLDV-REQ-F-001** (formatting): When the card list is started from the main menu, the system shall show the first 7 cards from the beginning of the card file. Rules: CCLDV-BR-001.
- **CCLDV-REQ-F-002** (design note): When the card list is started from another program with context 'enter' (from main menu option 3, or on return from card detail or card update), the system shall clear the saved first and last card positions, set the page to 1 and the last-page flag to 'not shown', and not read any screen input. Rules: CCLDV-BR-002.
- **CCLDV-REQ-F-003** (business rule): When the user arrives with PF3 from another program (such as leaving card detail or card update), or the list is re-entered from another program, the system shall reset the session to page 1 as a regular user and list the cards from the beginning of the card file. Rules: CCLDV-BR-003.
- **CCLDV-REQ-F-004** (business rule): While the card list fills a page going forward, when a card record passes the account and card-number filters, the system shall add its card number, account number and active status as the next row and, if it is the first row and the page number is 0, set the page number to 1. Rules: CCLDV-BR-004.
- **CCLDV-REQ-F-005** (business rule): When a page reaches 7 cards, the system shall stop filling the page and read one more card record ahead, without applying the filters, to decide whether a next page exists. Rules: CCLDV-BR-005.
- **CCLDV-REQ-F-006** (business rule): When the look-ahead read after a full page finds another card record, the system shall set the next page indicator to 'Y' and remember that card as the start of the next page. Rules: CCLDV-BR-006, CCLDV-BR-007.
- **CCLDV-REQ-F-007** (business rule): When a page is filled with the maximum of 7 cards and reading one card further reaches the end of the card file, the system shall record that no next page exists and, if no other message is set, show 'NO MORE RECORDS TO SHOW'. Rules: CCLDV-BR-008, CCLDV-BR-007.
- **CCLDV-REQ-F-008** (business rule): When the end of the card file is reached before the page holds 7 cards, the system shall stop reading, record that no next page exists, and show 'NO MORE RECORDS TO SHOW' if no other message is set. Rules: CCLDV-BR-009, CCLDV-BR-008.
- **CCLDV-REQ-F-009** (formatting): When the end of the card file is reached on page 1 with no card listed, the system shall show 'NO RECORDS FOUND FOR THIS SEARCH CONDITION.' instead of 'NO MORE RECORDS TO SHOW'. Rules: CCLDV-BR-010.
- **CCLDV-REQ-F-010** (business rule): When there is no input error and the user presses PF8 while a next page exists ('Y'), the system shall add one to the page number and list cards starting from the card found by the look-ahead read after the last card shown. Rules: CCLDV-BR-011.
- **CCLDV-REQ-F-011** (business rule): When there is no input error, exit, page change or valid selection (for example Enter with nothing selected, or PF8 with no next page), the system shall redisplay cards, applying any filters, starting from the first card of the page currently shown. Rules: CCLDV-BR-012.
- **CCLDV-REQ-F-012** (business rule): When there is no input error and the user presses PF7 while on page 1, the system shall redisplay page 1 starting from its first card with the message 'NO PREVIOUS PAGES TO DISPLAY'. Rules: CCLDV-BR-013, CCLDV-BR-014.
- **CCLDV-REQ-F-013** (business rule): When there is no input error and the user presses PF7 while not on page 1, the system shall subtract one from the page number and read backward from the first card of the current page, skipping that card itself. Rules: CCLDV-BR-015.
- **CCLDV-REQ-F-014** (business rule): While reading backward, the system shall place each card that passes the account and card-number filters into the rows from row 7 up to row 1, stop when row 1 is filled, and make the card in row 1 the new first card of the page. Rules: CCLDV-BR-016.
- **CCLDV-REQ-F-015** (design note): When the user pages backward, the system shall set the next page indicator to 'Y' and remember the first card of the page just left as the start of the next page, so that PF8 returns to that page. Rules: CCLDV-BR-017.
- **CCLDV-REQ-F-016** (design note): When the user presses any key other than PF8, the system shall reset the last-page flag to 'not shown'. Rules: CCLDV-BR-018.
- **CCLDV-REQ-F-017** (formatting): When the user presses PF8 on the last page for the first time, the system shall show the page again with the instruction 'TYPE S FOR DETAIL, U TO UPDATE ANY RECORD' and remember that the last page has been shown. Rules: CCLDV-BR-019.
- **CCLDV-REQ-F-018** (formatting): When the user presses PF8 again on a last page that has already been shown, the system shall redisplay that page with the message 'NO MORE PAGES TO DISPLAY'. Rules: CCLDV-BR-020.
- **CCLDV-REQ-F-019** (formatting): The system shall show 'TYPE S FOR DETAIL, U TO UPDATE ANY RECORD' on the card list in every case not otherwise covered, except when the message is 'NO RECORDS FOUND FOR THIS SEARCH CONDITION.' or a filter is in error. Rules: CCLDV-BR-021.
- **CCLDV-REQ-F-020** (business rule): When the user presses PF3 and the originating program is the card list, the system shall transfer control to the main menu program ('COMEN01C') with the shared context, ending the card list. Rules: CCLDV-BR-022.
