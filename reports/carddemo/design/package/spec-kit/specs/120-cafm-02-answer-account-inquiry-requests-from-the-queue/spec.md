# Feature specification: Answer account inquiry requests from the queue

**Feature:** CAFM-C02 · Card Authorization and Fraud Management · Unclassified

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (CAFM-C02)

As a requesting system, I want to send an account inquiry message and receive the account's details on a reply queue, so that I can see an account's status, balances and limits without direct file access.

A message service that answers account inquiry requests from other systems with the account's status, balances, limits and dates, so they never read the account file directly. Each request is answered on the account reply queue and matched to the request by its message and correlation ids. It must never answer a malformed or unknown-account request with account data, and it must never alter the stored values it reports.

**Acceptance scenarios:**

1. **Given** trigger message queue name: CARD.DEMO.REQUEST.ACCT, **when** the account inquiry transaction (CDRA) is started by an MQ trigger, **then** Requests are read from CARD.DEMO.REQUEST.ACCT; replies go to 'CARD.DEMO.REPLY.ACCT'; errors go to 'CARD.DEMO.ERROR'. (CAFM-C02-AC-01)
2. **Given** requests waiting: 3, **when** account inquiry service runs, **then** All 3 requests are answered; after a further 5 seconds with no message the queues are closed and the task ends. (CAFM-C02-AC-02)
3. **Given** requests waiting: 0, **when** account inquiry service runs, **then** The service waits 5 seconds, finds nothing, closes the queues and ends without sending any reply. (CAFM-C02-AC-03)
4. **Given** requests waiting: 2, **when** account inquiry service runs, **then** Request 1 and its reply are committed before request 2 is taken; request 2 and its reply are committed when the task ends. (CAFM-C02-AC-04)
5. **Given** request message: INQA00000012345, **when** a request is taken successfully, **then** Function code is 'INQA' and account number is 00000012345; the reply carries the request's message id and correlation id. (CAFM-C02-AC-05)
6. **Given** request reply-to queue: MY.REPLY.Q, **when** account inquiry service runs, **then** The reply still goes to 'CARD.DEMO.REPLY.ACCT'. (CAFM-C02-AC-06)
7. **Given** request message ID: MSG0001; request correlation ID: CORR0001; MQPUT result: OK, **when** a reply is ready for the current request, **then** The reply is put on 'CARD.DEMO.REPLY.ACCT' with message ID MSG0001 and correlation ID CORR0001 (CAFM-C02-AC-07)
8. **Given** reply queue: 'CARD.DEMO.REPLY.ACCT'; MQPUT result: failed (queue full), **when** a reply is ready for the current request, **then** 'MQPUT ERR' is recorded with the condition and reason codes, the error is sent to the error queue, and the queues are closed and the run ends (CAFM-C02-AC-08)
9. **Given** function code: 'INQA'; account ID: 00000000001, **when** the function code is not 'INQA' or the account key is zero or less, **then** The request is accepted and the account file is read for account 00000000001 (CAFM-C02-AC-09)
10. **Given** function code: INQA; account number: 00000012345, **when** a request has function code 'INQA' and an account number greater than zero, **then** Account 00000012345 is looked up in ACCTDAT. (CAFM-C02-AC-10)
11. **Given** account file response: DISABLED (84), **when** reading the account file returns anything other than found or not found, **then** Error record with 'ERROR WHILE READING ACCTF', condition 84 and the input queue name is put to 'CARD.DEMO.ERROR'. (CAFM-C02-AC-11)
12. **Given** account file response: DISABLED (84); requests waiting: 2, **when** such an account file error occurs, **then** No reply is sent for the first request; the task ends and the second request stays on the queue for the next trigger. (CAFM-C02-AC-12)
13. **Given** account file: disabled, **when** reading the account file fails for any reason other than account not found, **then** No reply is sent; an error record goes to 'CARD.DEMO.ERROR' and the task ends. (CAFM-C02-AC-13)
14. **Given** MQGET condition code: 2 (failed); reason code: 2016 (get inhibited), **when** taking a request fails for any reason other than no message being available, **then** Error record 'INP MQGET ERR:' with codes 02 and 02016 is put to 'CARD.DEMO.ERROR'; the task ends. (CAFM-C02-AC-14)
15. **Given** input queue open: fails, **when** the trigger data cannot be retrieved, or the input or reply queue cannot be opened, **then** Error record 'INP MQOPEN ERR' with the input queue name goes to 'CARD.DEMO.ERROR'; no requests are processed. (CAFM-C02-AC-15)
16. **Given** reply queue open: fails, **when** the trigger data cannot be retrieved, or the input or reply queue cannot be opened, **then** Error record 'OUT MQOPEN ERR' with queue 'CARD.DEMO.REPLY.ACCT' goes to 'CARD.DEMO.ERROR'; the task ends. (CAFM-C02-AC-16)
17. **Given** error queue open: fails, **when** the error queue 'CARD.DEMO.ERROR' cannot be opened, **then** 'ERR MQOPEN ERR' is written to the log and the task ends before any request is read. (CAFM-C02-AC-17)
18. **Given** An 'INQA' request for account 00000000001, and that account is on the account file, **when** The inquiry service answers the request, **then** The reply contains 'ACCOUNT ID : ', 'ACCOUNT STATUS : ', 'BALANCE : ', 'CREDIT LIMIT : ', 'CASH LIMIT : ', 'OPEN DATE : ', 'EXPR DATE : ', 'REIS DATE : ', 'CREDIT BAL : ', 'DEBIT BAL : ' and 'GROUP ID : ', each followed by the account's stored value unchanged, and 'CREDIT BAL : ' and 'DEBIT BAL : ' carry the current billing cycle's credit and debit (CAFM-C02-AC-18)
19. **Given** An account found by an 'INQA' request with a stored current balance of 1234.56, **when** The reply is built, **then** The value after 'BALANCE : ' is 12 characters long, has no decimal point, has the digits of 1234.56 with two implied decimal places, carries its sign in the last digit, and is exactly the stored value. Every other amount in the reply follows the same format (CAFM-C02-AC-19)
20. **Given** An 'INQA' request for account 00000000099, which is not on the account file, **when** The inquiry service answers the request, **then** The reply reads 'INVALID REQUEST PARAMETERS ACCT ID : 00000000099' and contains no account details (CAFM-C02-AC-20)

## Requirements

### Functional requirements

- **CAFM-REQ-F-014** (design note): When the account inquiry transaction (CDRA) is started by an MQ trigger, the system shall read requests from the queue named in the trigger message, send replies to the queue 'CARD.DEMO.REPLY.ACCT' and send error records to the queue 'CARD.DEMO.ERROR'. Rules: CAFM-BR-013.
- **CAFM-REQ-F-015** (business rule): The system shall take request messages one at a time, waiting up to 5 seconds for each, process and answer each one, and stop when no message arrives within 5 seconds, then close the queues it opened and end the task. Rules: CAFM-BR-014.
- **CAFM-REQ-N-002** (design note): The system shall take each request and put its reply as one unit of work committed before the next request is taken, with the last request's unit of work committed when the task ends. Rules: CAFM-BR-015.
- **CAFM-REQ-F-016** (design note): When a request is taken successfully, the system shall keep its message id and correlation id for the reply and read the first 4 characters as the function code and the next 11 digits as the account number. Rules: CAFM-BR-016.
- **CAFM-REQ-F-017** (historical artifact): The system shall always send replies to 'CARD.DEMO.REPLY.ACCT' and shall not use the reply-to queue named in the request. Rules: CAFM-BR-017.
- **CAFM-REQ-F-018** (design note): When a reply is ready for the current request, the system shall put the reply on the account reply queue carrying the request's message and correlation identifiers. Rules: CAFM-BR-018.
- **CAFM-REQ-F-019** (design note): If putting the reply fails, then the system shall record 'MQPUT ERR', publish the error and end the run. Rules: CAFM-BR-018.
- **CAFM-REQ-F-020** (business rule): If the function code is not 'INQA' or the account number is zero or less, then the system shall reply 'INVALID REQUEST PARAMETERS ACCT ID : ' with the account number, followed by 'FUNCTION : ' with the function code, without reading the account file. Rules: CAFM-BR-019, CAFM-BR-020.
- **CAFM-REQ-F-021** (business rule): When a request has function code 'INQA' and an account number greater than zero, the system shall read that account from the account file (ACCTDAT). Rules: CAFM-BR-021.
- **CAFM-REQ-F-022** (formatting): When the account is found, the system shall reply with 'ACCOUNT ID : ', 'ACCOUNT STATUS : ', 'BALANCE : ', 'CREDIT LIMIT : ', 'CASH LIMIT : ', 'OPEN DATE : ', 'EXPR DATE : ', 'REIS DATE : ', 'CREDIT BAL : ', 'DEBIT BAL : ' and 'GROUP ID : ', each followed by the stored value unchanged, the credit and debit balances being the current billing cycle's. Rules: CAFM-BR-022.
- **CAFM-REQ-F-023** (formatting): The system shall show amounts in the reply as 12 digits with two implied decimal places, no decimal point and the sign carried in the last digit, exactly as stored. Rules: CAFM-BR-023.
- **CAFM-REQ-F-024** (business rule): When the account is not on the account file, the system shall reply 'INVALID REQUEST PARAMETERS ACCT ID : ' followed by the 11-digit account number. Rules: CAFM-BR-024.
- **CAFM-REQ-F-025** (error handling): If reading the account file returns anything other than found or not found, then the system shall put an error record on 'CARD.DEMO.ERROR' holding the message 'ERROR WHILE READING ACCTF' (cut to 25 characters), the file response and reason codes and the input queue name, send no reply, close the open queues and end the task, with the request just taken committed as consumed. Rules: CAFM-BR-025, CAFM-BR-026, CAFM-BR-027.
- **CAFM-REQ-F-026** (error handling): If taking a request fails for any reason other than no message being available, then the system shall put an error record with 'INP MQGET ERR:', the condition and reason codes and the input queue name on the error queue, close the open queues and end the task. Rules: CAFM-BR-028.
- **CAFM-REQ-F-027** (error handling): If the trigger data cannot be retrieved, or the input or reply queue cannot be opened, then the system shall put an error record ('CICS RETREIVE' with the response codes, 'INP MQOPEN ERR' or 'OUT MQOPEN ERR' respectively) on the error queue and end the task. Rules: CAFM-BR-029.
- **CAFM-REQ-F-028** (error handling): If the error queue 'CARD.DEMO.ERROR' cannot be opened, then the system shall write 'ERR MQOPEN ERR' with the condition and reason codes to the job log and end the task. Rules: CAFM-BR-030.
