# Feature specification: Purge expired pending authorizations

**Feature:** CAFM-C01 · Card Authorization and Fraud Management · Unclassified

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (CAFM-C01)

As a card operations team, I want pending authorizations that have reached their expiry age removed from the authorization database by a batch job, so that the pending authorization store holds only current authorizations.

A scheduled job for the card operations team that works through every account's pending authorization summary, deletes each authorization detail that has reached the expiry age, and reduces the account's approved or declined counts and totals for each deleted detail. It deletes a summary once its adjusted approved count is zero or below. It must never delete an authorization younger than the expiry days, and it must stop the run if a deletion fails instead of carrying on with the store half purged.

**Acceptance scenarios:**

1. **Given** SYSIN: 00,00001,00001,Y, **when** Purge Parameter Setup runs, **then** Expiry days is 0 (numeric, so used as given) and checkpoint frequency stays '00001'. (CAFM-C01-AC-01)
2. **Given** P-EXPIRY-DAYS: 'AB'; P-CHKP-FREQ: spaces, **when** Purge Parameter Setup runs, **then** Expiry days defaults to 5 and checkpoint frequency defaults to 5. (CAFM-C01-AC-02)
3. **Given** P-EXPIRY-DAYS: 30; P-CHKP-FREQ: 00000, **when** Purge Parameter Setup runs, **then** Expiry days is 30 and checkpoint frequency is set to 5. (CAFM-C01-AC-03)
4. **Given** Job: CBPAUP0J, **when** expired-authorization purge job runs, **then** Step STEP01 runs DFSRRC00 with PARM 'BMP,CBPAUP0C,PSBPAUTB'. (CAFM-C01-AC-04)
5. **Given** Control values: 00,00001,00001,Y; Authorization age: 0 days (made today), **when** expired-authorization purge job runs, **then** The authorization qualifies for deletion, because its age is not less than 0 expiry days. (CAFM-C01-AC-05)
6. **Given** Control values: 00,00001,00001,Y, **when** expired-authorization purge job runs, **then** Debug lines such as 'DEBUG: AUTH SMRY READ : ' are printed and 'CHKP SUCCESS: AUTH COUNT - ' is shown after every checkpoint. (CAFM-C01-AC-06)
7. **Given** Summaries in database: 2; Details under first summary: 3, of which 1 expired, **when** pending authorization purge runs, **then** All 3 details of the first summary are checked and 1 is deleted before the second summary is read; the run stops when the summary read returns end of database. (CAFM-C01-AC-07)
8. **Given** Stored date key: 74964; Today (YYDDD): 25040, **when** pending authorization purge runs, **then** Authorization date is 25035 and age is 5 days. (CAFM-C01-AC-08)
9. **Given** Expiry days: 5; Age: 5, **when** an authorization's age is at least the expiry days, **then** Qualified for deletion. (CAFM-C01-AC-09)
10. **Given** Expiry days: 5; Age: 4, **when** an authorization's age is at least the expiry days, **then** Kept. (CAFM-C01-AC-10)
11. **Given** Qualified for deletion: Yes; Delete status: blank (success), **when** an authorization detail qualifies for deletion, **then** Detail removed and '# DETAILS REC DELETED' count increases by 1. (CAFM-C01-AC-11)
12. **Given** Delete status: any non-blank code, **when** deleting an authorization detail fails, **then** Messages 'AUTH DETAIL DELETE FAILED :' and 'CBPAUP0C ABENDING ...' are shown and the job ends with return code 16. (CAFM-C01-AC-12)
13. **Given** Summary approved count: 3; Summary approved total: $450.00; Detail response code: '00'; Detail approved amount: $120.00, **when** an authorization detail qualifies for purge and its response code is '00' (approved), **then** Approved count becomes 2 and approved total becomes $330.00 in the run's working copy; the stored summary is unchanged. (CAFM-C01-AC-13)
14. **Given** Approved count after purge: 0; Declined count after purge: 2, **when** all of an account summary's details have been checked, **then** The summary is deleted even though declined authorizations remain. (CAFM-C01-AC-14)
15. **Given** PA-APPROVED-AUTH-CNT: 0; DIBSTAT: spaces, **when** the approved authorization count (`PA-APPROVED-AUTH-CNT`) of the processed summary is zero or below, **then** The summary segment is deleted and '# SUMMARY REC DELETED :' at end of run counts it. (CAFM-C01-AC-15)
16. **Given** PA-APPROVED-AUTH-CNT: 2, **when** the approved authorization count (`PA-APPROVED-AUTH-CNT`) of the processed summary is zero or below, **then** The summary is kept. (CAFM-C01-AC-16)
17. **Given** PA-APPROVED-AUTH-CNT: 0; DIBSTAT: GE, **when** the approved authorization count (`PA-APPROVED-AUTH-CNT`) of the processed summary is zero or below, **then** 'AUTH SUMMARY DELETE FAILED :' is displayed with the account id, then 'CBPAUP0C ABENDING ...' and the run ends with return code 16. (CAFM-C01-AC-17)
18. **Given** An account summary in the purge job's working copy has declined count 3 and declined total 200.00, and one of its authorization details has response code '05' and transaction amount 40.00 and has qualified for purge, **when** The purge processes that detail, **then** The working copy shows declined count 2 and declined total 160.00, the approved count and approved total are unchanged, and the stored summary record is not rewritten (CAFM-C01-AC-18)

## Requirements

### Functional requirements

- **CAFM-REQ-F-001** (design note): The system shall capture the current date, use the supplied expiry days when numeric or else default them to 5, and default the checkpoint frequency to 5 when it is spaces, 0 or low-values. Rules: CAFM-BR-001.
- **CAFM-REQ-N-001** (design note): The system shall run the purge program (CBPAUP0C) as an IMS batch message program with program specification block PSBPAUTB, using the IMS PSB and DBD libraries. Rules: CAFM-BR-002.
- **CAFM-REQ-F-002** (business rule): The system shall run the expired-authorization purge job with the control values '00,00001,00001,Y', meaning authorizations 0 or more days old count as expired, a checkpoint is taken after more than 1 authorization summary is processed, every checkpoint is reported, and debug messages are on. Rules: CAFM-BR-003.
- **CAFM-REQ-F-003** (design note): The system shall read each account's pending authorization summary in turn until the end of the database, check every authorization detail under that summary for expiry, delete each detail that qualifies, and then move on to the next summary. Rules: CAFM-BR-004.
- **CAFM-REQ-F-004** (business rule): The system shall work out each authorization's date as 99999 minus its stored inverted date key (Julian YYDDD), and its age as today's Julian date (YYDDD) minus that date. Rules: CAFM-BR-005.
- **CAFM-REQ-F-005** (business rule): When an authorization's age is at least the expiry days, the system shall mark it as qualified for deletion. Rules: CAFM-BR-006.
- **CAFM-REQ-F-006** (business rule): When an authorization's age is less than the expiry days, the system shall mark it as not qualified and keep it. Rules: CAFM-BR-006.
- **CAFM-REQ-F-007** (business rule): When an authorization detail qualifies for deletion, the system shall delete it from the pending authorization detail segment (PAUTDTL1) and add 1 to the details-deleted count. Rules: CAFM-BR-007.
- **CAFM-REQ-F-008** (error handling): If deleting an authorization detail fails, then the system shall display 'AUTH DETAIL DELETE FAILED :' with the status and 'AUTH APP ID :' with the account, then display 'CBPAUP0C ABENDING ...' and end the run with return code 16. Rules: CAFM-BR-008.
- **CAFM-REQ-F-009** (business rule): When an authorization detail qualifies for purge and its response code is '00' (approved), the system shall subtract 1 from the account summary's approved count and subtract the detail's approved amount from the summary's approved total. Rules: CAFM-BR-009.
- **CAFM-REQ-F-010** (business rule): When an authorization detail qualifies for purge and its response code is anything other than '00', the system shall subtract 1 from the account summary's declined count and subtract the detail's transaction amount from the summary's declined total. Rules: CAFM-BR-010.
- **CAFM-REQ-F-011** (business rule): The system shall make the approved and declined count and total reductions in its working copy of the summary only and shall never rewrite the summary record. Rules: CAFM-BR-009, CAFM-BR-010.
- **CAFM-REQ-F-012** (business rule): When all of an account summary's details have been checked and the adjusted approved authorization count is zero or below, the system shall delete the pending authorization summary from the summary store (DLI:PAUTSUM0). Rules: CAFM-BR-011, CAFM-BR-012.
- **CAFM-REQ-F-013** (business rule): If deleting the pending authorization summary fails, then the system shall abend the run. Rules: CAFM-BR-012.

### Needs clarification

- SME-028: The authorization purge job receives the parameters '00,00001,00001,Y'. What does each value mean (for example expiry days or checkpoint frequency), and would '00' mean authorizations expire after zero days? (Card authorization operations) On CAFM-BR-001, CAFM-BR-012, CAFM-BR-003, CAFM-BR-004, CAFM-BR-009, CAFM-BR-010, CAFM-BR-006, CAFM-BR-008.
- SME-029: When should a pending-authorization summary be deleted: only when both the approved and declined counts are zero and no unexpired details remain under it? (Today the code checks the approved count twice.) (Card authorization business analyst) On CAFM-BR-001, CAFM-BR-012, CAFM-BR-003, CAFM-BR-004, CAFM-BR-009, CAFM-BR-010, CAFM-BR-006, CAFM-BR-008.
- DEF-004: Is this intended? The summary-delete test checks the approved count twice ('PA-APPROVED-AUTH-CNT <= 0 AND PA-APPROVED-AUTH-CNT <= 0'), so a summary is deleted when no approved authorizations remain even if declined ones do; the declined count was almost certainly meant for the second test. (Subject-matter expert) On CAFM-BR-009, CAFM-BR-010, CAFM-BR-011.
- DEF-081: Is this intended? The age is a plain subtraction of YYDDD values, so across a year end it is wrong: an authorization dated 25365 checked on 26001 gets an age of 636 days and is purged after one day. Also, the shipped job passes '00' as expiry days, which is numeric, so the default of 5 is skipped and every detail is purged on every run. (Subject-matter expert) On CAFM-BR-006, CAFM-BR-007, CAFM-BR-008.
- DEF-140: Is this intended? The job passes 00 expiry days, which CBPAUP0C accepts as numeric, so every authorization (including ones made today) qualifies for deletion instead of the program default of 5 days. (Subject-matter expert) On CAFM-BR-003.
