# Feature specification: Search and view card details

**Feature:** CCLDV-C04 · Credit Card List Detail View and Update · Customer Data Setup

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (CCLDV-C04)

As a card operations user, I want to enter an account and card number and see that card's details, so that I can check the card's embossed name, expiry and status.

Lets card operations staff enter an account number and a 16-digit card number and see that card's embossed name, expiry month and year, and active status. The card is looked up by card number alone. It must reject missing or non-numeric input with the exact messages, and must say clearly when the card is not found or the card file cannot be read.

**Acceptance scenarios:**

1. **Given** Account entered: '*'; Card number entered: 4111111111111111, **when** the account or card number entered on the card detail screen is '*' or blank, **then** The account is treated as not supplied and reported as 'Account number not provided' (CCLDV-C04-AC-01)
2. **Given** Card number entered: blank, **when** the account or card number entered on the card detail screen is '*' or blank, **then** The card number is treated as not supplied (CCLDV-C04-AC-02)
3. **Given** Account entered: 00000000000; Card number entered: 4111111111111111, **when** the account is not supplied (blank, '*' or all zeros) after the user presses Enter, **then** Input rejected with 'Account number not provided'; no card is looked up (CCLDV-C04-AC-03)
4. **Given** Account entered: blank, **when** the account is not supplied (blank, '*' or all zeros) after the user presses Enter, **then** Input rejected; saved account becomes 0 (CCLDV-C04-AC-04)
5. **Given** Account entered: blank, **when** the account is found missing after the user presses Enter, **then** The account field shows '*' in red (CCLDV-C04-AC-05)
6. **Given** Account entered: 1234567890A, **when** a supplied account is not entirely numeric, **then** Input rejected with 'ACCOUNT FILTER,IF SUPPLIED MUST BE A 11 DIGIT NUMBER'; account shown in red (CCLDV-C04-AC-06)
7. **Given** Account entered: 00000000001, **when** a supplied account is an 11-digit number that is not all zeros, **then** Account accepted and saved as the current account (CCLDV-C04-AC-07)
8. **Given** Account number: 00000000001; Card number: (blank), **when** the user resubmits the card detail screen and the card number is blank, '*', spaces or all zeros, **then** Error 'Card number not provided'; card field shows '*' in red; no card is looked up (CCLDV-C04-AC-08)
9. **Given** Account number: (blank); Card number: 0000000000000000, **when** the user resubmits the card detail screen and the card number is blank, '*', spaces or all zeros, **then** The card is treated as missing, but the account message set first is kept (both missing then gives 'No input received') (CCLDV-C04-AC-09)
10. **Given** Account number: 00000000001; Card number: 41111111111X1111, **when** the user resubmits the card detail screen and the card number is not made up of 16 digits, **then** Error 'CARD ID FILTER,IF SUPPLIED MUST BE A 16 DIGIT NUMBER'; card field in red; no card is looked up (CCLDV-C04-AC-10)
11. **Given** Account number: ABC; Card number: 41111111111X1111, **when** the user resubmits the card detail screen and the card number is not made up of 16 digits, **then** The account error 'ACCOUNT FILTER,IF SUPPLIED MUST BE A 11 DIGIT NUMBER' is shown because it was set first; both fields are in red (CCLDV-C04-AC-11)
12. **Given** Card number: 4111111111111111, **when** the card number entered is a 16-digit number other than all zeros, **then** The card number is accepted and saved for the lookup (CCLDV-C04-AC-12)
13. **Given** Account number: (blank); Card number: *, **when** the user resubmits the card detail screen with both the account number and the card number missing (blank, '*' or all zeros), **then** Message 'No input received'; both fields show '*' in red; no lookup (CCLDV-C04-AC-13)
14. **Given** Account number: 00000000000; Card number: (blank), **when** the user resubmits the card detail screen with both the account number and the card number missing (blank, '*' or all zeros), **then** Message 'No input received' replaces 'Account number not provided' (CCLDV-C04-AC-14)
15. **Given** Account entered: 1234567890A, **when** the user presses Enter on the card detail screen and PF3 was not pressed, **then** Screen redisplayed with 'ACCOUNT FILTER,IF SUPPLIED MUST BE A 11 DIGIT NUMBER'; no card lookup (CCLDV-C04-AC-15)
16. **Given** Account entered: 00000000001; Card number entered: 4111111111111111, **when** the user presses Enter on the card detail screen and PF3 was not pressed, **then** Card is looked up and its details are shown (CCLDV-C04-AC-16)
17. **Given** Key: PF7; Card number: 4111111111111111; Account number: 00000000001, **when** the user presses any key other than Enter, PF3 or PF15 on the card detail screen, **then** Processed as Enter: input is checked again and the card is looked up again (CCLDV-C04-AC-17)
18. **Given** Key: PF15, **when** the user presses any key other than Enter, PF3 or PF15 on the card detail screen, **then** Treated as PF3 (exit) (CCLDV-C04-AC-18)
19. **Given** Account entered: 00000000001; Card number entered: 4111111111111111 (belongs to account 00000000099), **when** a card lookup is made, **then** The card is found and its details are shown (CCLDV-C04-AC-19)
20. **Given** Card number: 4111111111111111 (on file, expiry 2027-03, status Y), **when** the card is found, **then** Screen shows the embossed name, month 03, year 2027, status Y and ' Displaying requested details' (CCLDV-C04-AC-20)
21. **Given** Card number entered: 9999999999999999 (not on file), **when** no card exists with the requested card number, **then** 'Did not find cards for this search condition'; both fields shown in red (CCLDV-C04-AC-21)
22. **Given** Card found: no, **when** the card detail screen is shown and no information message has been set, **then** Info line shows 'Please enter Account and Card Number' (CCLDV-C04-AC-22)
23. **Given** Card found: yes, **when** the card detail screen is shown and no information message has been set, **then** Info line shows ' Displaying requested details' (CCLDV-C04-AC-23)
24. **Given** Card number: (blank); Account number: 00000000001, **when** card detail screen runs, **then** Error line 'Card number not provided'; info line 'Please enter Account and Card Number' (CCLDV-C04-AC-24)
25. **Given** Saved account: 00000000001; Saved card: 4111111111111111, **when** the card detail screen is shown with session details, **then** Both values are shown in the search fields (CCLDV-C04-AC-25)
26. **Given** Card number typed: 41111111111X1111, **when** the card detail screen is shown with session details, **then** Saved card number becomes 0, so the card field is shown empty (in red) instead of echoing the entry (CCLDV-C04-AC-26)
27. **Given** Caller: COCRDLIC; Last screen: COCRDLI, **when** the card detail screen was reached from the card list (last screen COCRDLI, caller COCRDLIC), **then** Account and card fields cannot be changed (CCLDV-C04-AC-27)
28. **Given** Caller: main menu, **when** the card detail screen was reached from the card list (last screen COCRDLI, caller COCRDLIC), **then** Account and card fields can be typed in (CCLDV-C04-AC-28)
29. **Given** Card number: 41111111111X1111, **when** a search field fails its check, **then** Card field in red (CCLDV-C04-AC-29)
30. **Given** Account and card: card not found on file, **when** a search field fails its check, **then** Both fields in red (CCLDV-C04-AC-30)
31. **Given** Account number: 00000000001; Card number: (blank), **when** card detail screen runs, **then** Cursor on the card field (CCLDV-C04-AC-31)
32. **Given** Account number: ABC; Card number: (blank), **when** card detail screen runs, **then** Cursor on the account field (CCLDV-C04-AC-32)
33. **Given** a valid 11-digit account number and a valid 16-digit card number are entered on the card detail screen, and the card master cannot be read for a reason other than 'not found' (for example the file is unavailable), **when** the user presses Enter, **then** the search is rejected, no card details are shown, the account field is shown in red and the error line shows 'File Error: READ on CARDDAT returned RESP <code>,RESP2 <code>' with the two response codes from the failed read (CCLDV-C04-AC-33)

## Requirements

### Functional requirements

- **CCLDV-REQ-F-034** (business rule): When the account or card number entered on the card detail screen is '*' or blank, the system shall treat that search criterion as not supplied. Rules: CCLDV-BR-032.
- **CCLDV-REQ-F-035** (business rule): If the account is not supplied (blank, '*' or all zeros) after the user presses Enter, then the system shall reject the input, show 'Account number not provided' if no other message is already set, reset the saved account to 0 and redisplay the account field as '*' in red. Rules: CCLDV-BR-033, CCLDV-BR-034.
- **CCLDV-REQ-F-036** (business rule): If a supplied account is not entirely numeric, then the system shall reject the input, show the account in red with 'ACCOUNT FILTER,IF SUPPLIED MUST BE A 11 DIGIT NUMBER' if no other message is already set, and reset the saved account to 0. Rules: CCLDV-BR-035.
- **CCLDV-REQ-F-037** (business rule): When a supplied account is an 11-digit number that is not all zeros, the system shall accept it and keep it as the current account for the session. Rules: CCLDV-BR-036.
- **CCLDV-REQ-F-038** (business rule): If the user resubmits the card detail screen and the card number is blank, '*', spaces or all zeros, then the system shall treat it as an input error, show the field as '*' in red, show 'Card number not provided' unless an earlier message is already set, clear the saved card number to 0 and not look up a card. Rules: CCLDV-BR-037.
- **CCLDV-REQ-F-039** (business rule): If the user resubmits the card detail screen and the card number is not made up of 16 digits, then the system shall treat it as an input error, show the card field in red, show 'CARD ID FILTER,IF SUPPLIED MUST BE A 16 DIGIT NUMBER' unless an earlier message is already set, and clear the saved card number to 0. Rules: CCLDV-BR-038.
- **CCLDV-REQ-F-040** (business rule): When the card number entered is a 16-digit number other than all zeros, the system shall accept it and save it in the shared session details as the card to look up. Rules: CCLDV-BR-039.
- **CCLDV-REQ-F-041** (business rule): If the user resubmits the card detail screen with both the account number and the card number missing (blank, '*' or all zeros), then the system shall show 'No input received' in place of any other message, mark both fields with '*' in red, and not look up a card. Rules: CCLDV-BR-040.
- **CCLDV-REQ-F-042** (business rule): When the user presses Enter on the card detail screen and PF3 was not pressed, the system shall check the entered account and card number, redisplay the screen with the message if a check fails, and otherwise look up the card and show its details. Rules: CCLDV-BR-041.
- **CCLDV-REQ-F-043** (business rule): When the user presses any key other than Enter, PF3 or PF15 on the card detail screen, the system shall show no error and treat the key as Enter, checking the input again and repeating the search. Rules: CCLDV-BR-042.
- **CCLDV-REQ-F-044** (business rule): When a card lookup is made, the system shall read the card master (CARDDAT) by the 16-digit card number only, and shall not check that the card belongs to the account entered. Rules: CCLDV-BR-043.
- **CCLDV-REQ-F-045** (formatting): When the card is found, the system shall show ' Displaying requested details' with the card's embossed name, expiry month, expiry year and active status. Rules: CCLDV-BR-044.
- **CCLDV-REQ-F-046** (business rule): If no card exists with the requested card number, then the system shall reject the search, show both the account and the card number in red, and show 'Did not find cards for this search condition'. Rules: CCLDV-BR-045.
- **CCLDV-REQ-F-047** (error handling): If reading the card master fails for any reason other than not found, then the system shall reject the search, show the account in red and show 'File Error: READ on CARDDAT returned RESP <code>,RESP2 <code>'. Rules: CCLDV-BR-046.
- **CCLDV-REQ-F-048** (formatting): When the card detail screen is shown and no information message has been set, the system shall show the information message 'Please enter Account and Card Number'. Rules: CCLDV-BR-047.
- **CCLDV-REQ-F-049** (formatting): The system shall show the current error message (if any) on the error line and the information message on the information line of the card detail screen. Rules: CCLDV-BR-048.
- **CCLDV-REQ-F-050** (formatting): When the card detail screen is shown with session details, the system shall show the saved account number and card number, leaving a field empty when its saved value is zero. Rules: CCLDV-BR-049.
- **CCLDV-REQ-F-051** (formatting): When the card detail screen was reached from the card list (last screen COCRDLI, caller COCRDLIC), the system shall show the account and card fields as protected (not editable) in the default colour, and otherwise shall leave them editable. Rules: CCLDV-BR-050.
- **CCLDV-REQ-F-052** (formatting): If a search field fails its check, then the system shall show that field in red, and show '*' in red in a field left blank on resubmission, even if the fields are protected. Rules: CCLDV-BR-051.
- **CCLDV-REQ-F-053** (formatting): The system shall place the cursor on the account field when it is invalid or blank, otherwise on the card field when that is invalid or blank, and otherwise on the account field. Rules: CCLDV-BR-052.
