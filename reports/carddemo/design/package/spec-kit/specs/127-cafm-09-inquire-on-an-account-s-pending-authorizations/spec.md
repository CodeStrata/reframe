# Feature specification: Inquire on an account's pending authorizations

**Feature:** CAFM-C09 · Card Authorization and Fraud Management · Unclassified

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (CAFM-C09)

As a customer service operator, I want to enter an account and see its customer, limits and pending-authorization totals, so that I can review the account's authorization activity.

Lets a customer service operator enter an account number and see the customer's name, address and phone, the account's credit and cash limits, and the pending-authorization totals, followed by the first page of authorizations. The account number must be entered and must be numeric. When there is no pending-authorization summary, the totals show zero and no authorizations are listed. Every failed lookup must say which record was missing or failed, word for word.

**Acceptance scenarios:**

1. **Given** session data: none, **when** the pending authorization summary is started with no session data, **then** An empty summary screen is shown with the cursor on the account number (CAFM-C09-AC-01)
2. **Given** passed account number: 00000000001; entry: first entry from main menu, **when** the summary screen is entered from another function for the first time, **then** Account 00000000001 details and its first page of pending authorizations are shown (CAFM-C09-AC-02)
3. **Given** passed account number: spaces, **when** the summary screen is entered from another function for the first time, **then** The account field is blank and no account details or authorizations are loaded (CAFM-C09-AC-03)
4. **Given** account number: blank; key pressed: Enter, **when** the user presses Enter with the account number blank, **then** Message 'Please enter Acct Id...' is shown and no authorizations are listed (CAFM-C09-AC-04)
5. **Given** Account ID: (blank); Key: Enter, **when** the operator presses Enter with Account ID blank, **then** Message 'Please enter Acct Id...' and no list is loaded (CAFM-C09-AC-05)

## Requirements

### Functional requirements

- **CAFM-REQ-F-082** (formatting): When the pending authorization summary is started with no session data, the system shall start a new session, mark it as re-entered and show an empty screen with the cursor on the account number field. Rules: CAFM-BR-084.
- **CAFM-REQ-F-083** (business rule): When the summary screen is entered from another function for the first time, the system shall mark the session as re-entered, use the passed account number if it is numeric (otherwise treat it as not supplied), load the account details and first page of authorizations, and display the screen with a full erase. Rules: CAFM-BR-085.
- **CAFM-REQ-F-084** (business rule): When the operator presses Enter with the Account ID blank, the system shall flag an error, show 'Please enter Acct Id...', clear the working account, put the cursor on Account ID and load no account details or authorizations. Rules: CAFM-BR-086, CAFM-BR-087.
- **CAFM-REQ-F-085** (business rule): When the operator presses Enter with an Account ID that is not entirely numeric, the system shall show 'Acct Id must be Numeric ...', flag an error, clear the working account, put the cursor on Account ID and load no account details or authorizations. Rules: CAFM-BR-088.
- **CAFM-REQ-F-086** (business rule): When the operator presses Enter with a numeric Account ID, the system shall save it as the current account for the session, process any row selection, reset to the first page, and reload the account details and the first five pending authorizations. Rules: CAFM-BR-089.
- **CAFM-REQ-F-087** (formatting): When the Enter processing completes, the system shall redisplay the screen with the Account ID field showing the accepted account, or blank when the entry was rejected. Rules: CAFM-BR-090.
- **CAFM-REQ-F-088** (design note): When a numeric account number is present, entered with Enter or passed in from the menu, the system shall look up the account's card cross-reference, account record, customer record and pending-authorization summary, and shall load the first page of authorizations only when a summary exists for the account. Rules: CAFM-BR-091.
- **CAFM-REQ-F-089** (design note): When the card cross-reference for the account is found, the system shall save the customer ID and card number from it in the session for later screens. Rules: CAFM-BR-092.
- **CAFM-REQ-F-090** (formatting): The system shall show the customer name as the first word of the first name, a space, the middle initial, a space, and the last name. Rules: CAFM-BR-093.
- **CAFM-REQ-F-091** (formatting): The system shall show address line 1 as address lines 1 and 2 joined by a comma, and address line 2 as address line 3, the state code and the first 5 digits of the ZIP code joined by commas, cutting each address line at its first double space. Rules: CAFM-BR-094.
- **CAFM-REQ-F-092** (formatting): The system shall show the customer ID, the first phone number, and the account's credit limit and cash credit limit from the account master as signed amounts with two decimals. Rules: CAFM-BR-095.
- **CAFM-REQ-F-093** (formatting): When a pending authorization summary exists for the account, the system shall show its approved count, declined count, approved amount, declined amount, credit balance and cash balance. Rules: CAFM-BR-096, CAFM-BR-097.
- **CAFM-REQ-F-094** (formatting): When no pending authorization summary exists for the account, the system shall show the approved and declined counts and amounts and the credit and cash balances as zero, and shall not list any authorizations. Rules: CAFM-BR-098, CAFM-BR-097.
- **CAFM-REQ-F-095** (error handling): If reading the pending authorization summary fails for any reason other than not found, then the system shall flag an error, show ' System error while reading AUTH Summary: Code:' followed by the database status code, put the cursor on Account ID and show the totals as zero. Rules: CAFM-BR-099.
- **CAFM-REQ-F-096** (error handling): If no card cross-reference exists for the account, then the system shall show 'Account:<account> not found in XREF file. Resp:<code> Reas:<code>', and on any other read failure of file CXACAIX shall flag an error and show 'Account:<account> System error while reading XREF file. Resp:<code> Reas:<code>'. Rules: CAFM-BR-100.
- **CAFM-REQ-F-097** (error handling): If the account record is not on the account file, then the system shall show 'Account:<account> not found in ACCT file. Resp:<code> Reas:<code>', and on any other read failure of file ACCTDAT shall flag an error and show 'Account:<account> System error while reading ACCT file. Resp:<code> Reas:<code>'. Rules: CAFM-BR-101.
- **CAFM-REQ-F-098** (error handling): If the customer record is not on the customer file, then the system shall show 'Customer:<customer> not found in CUST file. Resp:<code> Reas:<code>', and on any other read failure of file CUSTDAT shall flag an error and show 'Customer:<customer> System error while reading CUST file. Resp:<code> Reas:<code>'. Rules: CAFM-BR-102.
- **CAFM-REQ-F-099** (business rule): When the user presses PF3 on the summary screen, the system shall transfer control to the main menu (COMEN01C), passing the session data. Rules: CAFM-BR-103.
- **CAFM-REQ-F-100** (business rule): If the user presses any key other than Enter, PF3, PF7 or PF8, then the system shall flag an error and redisplay the screen with the message 'Invalid key pressed. Please see below...' and the cursor on the account number field. Rules: CAFM-BR-104.
