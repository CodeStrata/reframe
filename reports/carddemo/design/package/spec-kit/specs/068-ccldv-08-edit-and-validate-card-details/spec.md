# Feature specification: Edit and validate card details

**Feature:** CCLDV-C08 · Credit Card List Detail View and Update · Customer Data Setup

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (CCLDV-C08)

As a card operations user, I want to change a card's embossed name, active status and expiry date and have my changes checked, so that only valid card details are put forward for saving.

Lets card operations staff change a card's embossed name, active status and expiry month and year, and checks each change before it can be saved. The name may hold only letters and spaces, the status must be Y or N, the month must be 1-12 and the year 1950-2099. It must never put forward invalid details for saving, and it shows only the first failing check's message.

**Acceptance scenarios:**

1. **Given** embossed name: *; active status: Y, **when** the operator submits the card update screen, **then** Name is treated as not supplied; status 'Y' is taken as the new value. (CCLDV-C08-AC-01)
2. **Given** expiry month: (blank); expiry year: 2027, **when** the operator submits the card update screen, **then** Month is treated as not supplied; year 2027 is taken. (CCLDV-C08-AC-02)
3. **Given** Card name entered: *, **when** the user enters '*' or leaves the card name blank on the card update screen, **then** The name counts as not supplied (CCLDV-C08-AC-03)
4. **Given** Card active status entered: *, **when** the user enters '*' or leaves the card active status blank, **then** Status is treated as not supplied and fails the Y/N check if the card details are being edited (CCLDV-C08-AC-04)
5. **Given** Card active status entered: Y, **when** the user enters '*' or leaves the card active status blank, **then** 'Y' is taken as the new status (CCLDV-C08-AC-05)
6. **Given** Expiry month entered: *, **when** the user enters '*' or leaves the expiry month or expiry year blank on the card update screen, **then** The month counts as not supplied (CCLDV-C08-AC-06)
7. **Given** Expiry year entered: 2027, **when** the user enters '*' or leaves the expiry month or expiry year blank on the card update screen, **then** 2027 is taken as the new expiry year (CCLDV-C08-AC-07)
8. **Given** expiry day returned: 15, **when** card update screen runs, **then** New expiry day is 15. (CCLDV-C08-AC-08)
9. **Given** Entered card details: identical to fetched details, **when** the new card data equals the fetched data ignoring case, or the state is awaiting confirmation ('N') or done ('C'), **then** The screen reports 'No change detected with respect to values fetched.' and no further field editing is done. (CCLDV-C08-AC-09)
10. **Given** Fetched expiry month: 05; Entered expiry month: 05; Entered embossed name: same as fetched but in lower case, **when** the new card data equals the fetched data ignoring case, or the state is awaiting confirmation ('N') or done ('C'), **then** Case is ignored, so 'No change detected with respect to values fetched.' is reported. 26. **Given** Expiry year: 1949, **when** card details have been fetched and the user changes them, and the expiry year is missing, '*', blank or zeros, or is not between 1950 and 2099, **then** Error 'Invalid card expiry year' (CCLDV-C08-AC-26)

## Requirements

### Functional requirements

- **CCLDV-REQ-F-078** (design note): When the operator submits the card update screen with the embossed name, active status, expiry month or expiry year entered as '*' or left blank, the system shall treat that value as not supplied, and otherwise shall take the entry as the new value. Rules: CCLDV-BR-085, CCLDV-BR-086, CCLDV-BR-087, CCLDV-BR-088.
- **CCLDV-REQ-F-079** (design note): The system shall always take the expiry day exactly as returned by the screen, without the '*' or blank check, as the new expiry day written back to the card record. Rules: CCLDV-BR-089, CCLDV-BR-090.
- **CCLDV-REQ-F-080** (business rule): When the entered card details equal the fetched details ignoring upper/lower case, the system shall skip the field checks, report 'No change detected with respect to values fetched.' and leave the details shown (state 'S') without asking for confirmation. Rules: CCLDV-BR-091, CCLDV-BR-092, CCLDV-BR-093.
- **CCLDV-REQ-F-081** (business rule): When card details are shown and the operator submits name, status or expiry values that differ (ignoring upper/lower case) from the stored ones, the system shall run the name, status, expiry month and expiry year checks. Rules: CCLDV-BR-094.
- **CCLDV-REQ-F-082** (business rule): If the changed card name is missing, '*', blank or zeros, then the system shall reject the change with 'Card name not provided' and show '*' in the name field in red. Rules: CCLDV-BR-095.
- **CCLDV-REQ-F-083** (business rule): If the changed card name contains anything other than letters A-Z, a-z and spaces, then the system shall reject the change with 'Card name can only contain alphabets and spaces' and show the name in red. Rules: CCLDV-BR-096.
- **CCLDV-REQ-F-084** (business rule): If the entered details differ from those fetched and the card active status is not supplied, is '0', or is anything other than uppercase 'Y' or 'N', then the system shall reject the input with 'Card Active Status must be Y or N', unless an earlier field already set a message. Rules: CCLDV-BR-097, CCLDV-BR-098.
- **CCLDV-REQ-F-085** (business rule): If the changed expiry month is missing, '*', blank or zeros, or is not between 1 and 12, then the system shall reject the change with 'Card expiry month must be between 1 and 12' and show the month in red. Rules: CCLDV-BR-099.
- **CCLDV-REQ-F-086** (business rule): If the changed expiry year is missing, '*', blank or zeros, or is not between 1950 and 2099, then the system shall reject the change with 'Invalid card expiry year' and show the year in red. Rules: CCLDV-BR-100.
- **CCLDV-REQ-F-087** (formatting): When the expiry month or year was rejected because it was missing, blank or zeros, the system shall show '*' in that field in red. Rules: CCLDV-BR-101.
- **CCLDV-REQ-F-088** (business rule): When more than one card field fails its check, the system shall show only the message of the first failing check, in the order name, status, expiry month, expiry year. Rules: CCLDV-BR-102.
- **CCLDV-REQ-F-089** (business rule): If any changed value fails its check, then the system shall keep the screen in the changes-with-errors state ('E') and show 'Update card details presented above.' alongside the error message. Rules: CCLDV-BR-094, CCLDV-BR-103.
- **CCLDV-REQ-F-090** (business rule): When the changed values pass all checks, the system shall move to awaiting confirmation (state 'N') and show 'Changes validated.Press F5 to save'. Rules: CCLDV-BR-104.
- **CCLDV-REQ-F-091** (business rule): While the edits still have errors (state 'E'), the system shall not save and shall show the card details again in the same state. Rules: CCLDV-BR-105.
- **CCLDV-REQ-F-092** (formatting): When the card update screen is redisplayed after the operator has entered changes (stage 'E', 'N', 'C', 'L' or 'F'), the system shall show the operator's entered embossed name, active status, expiry month and expiry year, and the card's original expiry day. Rules: CCLDV-BR-106.
