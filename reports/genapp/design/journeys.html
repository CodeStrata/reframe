Unassigned programs

J01 Add a new customer

Customer service user · Create a new customer record and get the customer number the system assigns to it.

  1. General Insurance Customer Menu SSMAPC1: Start the customer transaction (SSC1) to open the customer screen; press CLEAR to start again with an empty screen if needed
  2. General Insurance Customer Menu SSMAPC1: Enter the customer's name, date of birth, house name and number, postcode, phones and email, choose option 2 (Add) and press Enter
  3. General Insurance Customer Menu SSMAPC1: If the option is not valid, correct it and press Enter again
  4. General Insurance Customer Menu SSMAPC1: Note the new customer number shown with 'New Customer Inserted', or read 'Error Adding Customer' and enter the details again
  5. General Insurance Customer Menu SSMAPC1: Press PF3 to end the transaction
1 capabilities, 8 requirements
  • Customer add, update and menu rec/unassigned#1
  • REQ-F-001 When the user chooses option '2' on the customer screen, the system shall send an add-customer request ('01ACUS') to the customer add program (LGACUS01) with customer number 0 and the entered details, after turning any null characters into spaces and the postcode into upper case.
  • REQ-F-002 When the add-customer request returns code 0, the system shall update the customer-number control queue, show the assigned customer number, clear the option field and display 'New Customer Inserted'.
  • REQ-F-003 When a new customer has been added successfully, the system shall lock the control queue 'GENACNTL', find its 'HIGH CUSTOMER' entry, rewrite that entry as 'HIGH CUSTOMER=' followed by the new customer number, leave the 'LOW CUSTOMER=' entry unchanged and then release the lock.
  • REQ-F-004 If the control queue 'GENACNTL' does not exist or has no 'HIGH CUSTOMER' entry, then the system shall write three entries to it: '**** GENAPP CNTL', 'LOW CUSTOMER=' and 'HIGH CUSTOMER=', each with the new customer number.
  • REQ-F-005 If the add-customer request returns a code greater than 0, then the system shall roll back the unit of work, display 'Error Adding Customer' and clear the screen data.
  • REQ-F-011 If the user enters an option other than '1' (inquire), '2' (add) or '4' (update), including blank or '3', then the system shall call no back-end program, display 'Please enter a valid option', place the cursor on the option field and wait for the next input under transaction 'SSC1'.
  • REQ-F-012 When the user presses PF3 on the customer screen, the system shall display 'Transaction ended' and end the conversation.
  • REQ-F-013 When the user presses CLEAR on the customer screen, the system shall redisplay an empty customer screen and continue under 'SSC1'.

J02 Update a customer's details

Customer service user · Find an existing customer and change their details so that the record stays current.

  1. General Insurance Customer Menu SSMAPC1: Start the customer transaction (SSC1) to open the customer screen
  2. General Insurance Customer Menu SSMAPC1: Enter the customer number, choose option 4 (Update) and press Enter to show the current details, or see 'No data was returned.'
  3. General Insurance Customer Menu SSMAPC1: Change the details on the screen and press Enter to save them
  4. General Insurance Customer Menu SSMAPC1: Read 'Customer details updated', or 'Error Updating Customer' and start again
  5. General Insurance Customer Menu SSMAPC1: Press PF3 to end the transaction
1 capabilities, 7 requirements
  • Customer add, update and menu rec/unassigned#1
  • REQ-F-006 When the user chooses option '4', the system shall first look up the customer ('01ICUS', LGICUS01) and display the current details.
  • REQ-F-007 If the customer lookup for option '4' returns a code greater than 0, then the system shall display 'No data was returned.' and stop.
  • REQ-F-008 When the user changes the displayed customer details and presses Enter, the system shall send an update request ('01UCUS') to the customer update program (LGUCUS01) with the customer number and all fields from the screen, after turning null characters into spaces and the postcode into upper case.
  • REQ-F-009 When the customer update returns code 0, the system shall display 'Customer details updated'.
  • REQ-F-010 If the customer update returns a code greater than 0, then the system shall display 'Error Updating Customer' and clear the screen data, without a rollback.
  • REQ-F-011 If the user enters an option other than '1' (inquire), '2' (add) or '4' (update), including blank or '3', then the system shall call no back-end program, display 'Please enter a valid option', place the cursor on the option field and wait for the next input under transaction 'SSC1'.
  • REQ-F-012 When the user presses PF3 on the customer screen, the system shall display 'Transaction ended' and end the conversation.

J03 Manage a motor policy

Policy administrator · Look up, add, change or delete a customer's motor policy so that the motor cover on record is correct.

  1. General Insurance Motor Policy Menu SSMAPP1: Start the motor policy transaction (SSP1) to open the motor policy screen
  2. General Insurance Motor Policy Menu SSMAPP1: Enter the customer and policy numbers and choose option 1 (Inquire) to see the policy's dates, vehicle details, accidents and premium, or see 'No data was returned.'
  3. General Insurance Motor Policy Menu SSMAPP1: To add a policy, enter the customer number, dates and vehicle details, choose option 2, and note the new policy number shown with 'New Motor Policy Inserted' (or read 'Customer does not exist' or 'Error Adding Motor Policy')
  4. General Insurance Motor Policy Menu SSMAPP1: To change a policy, choose option 4 to show its current details, edit them and press Enter; read 'Motor Policy Updated' or 'Error Updating Motor Policy'
  5. General Insurance Motor Policy Menu SSMAPP1: To remove a policy, enter the customer and policy numbers, choose option 3, and read 'Motor Policy Deleted' or 'Error Deleting Motor Policy'
  6. General Insurance Motor Policy Menu SSMAPP1: If the option is not valid, correct it and press Enter again
1 capabilities, 15 requirements
  • Motor policy inquire, add, delete and update rec/unassigned#2
  • REQ-F-014 The system shall offer on the motor policy screen (transaction SSP1) option '1' Inquire, '2' Add, '3' Delete and '4' Update.
  • REQ-F-015 If any other option is entered on the motor policy screen, then the system shall show 'Please enter a valid option' with the cursor on the option field.
  • REQ-F-016 When option '1' is entered, the system shall request the motor policy (request 01IMOT to LGIPOL01) for the entered customer and policy number and display issue date, expiry date, make, model, value, registration, colour, engine CC, manufacture date, premium and accident count.
  • REQ-F-017 If the motor policy inquiry returns a non-zero return code, then the system shall show 'No data was returned.' and clear the screen and request data for the next entry.
  • REQ-F-018 When option '2' is entered on the motor policy screen, the system shall add a motor policy (request 01AMOT to LGAPOL01) from the entered customer number, dates and vehicle details, always with payment 0, broker id 0 and a blank broker reference.
  • REQ-F-019 When the motor policy add succeeds, the system shall show the customer number, the newly assigned policy number and 'New Motor Policy Inserted', and clear the option.
  • REQ-F-020 If the motor policy add returns a non-zero code, then the system shall roll back the unit of work and show 'Customer does not exist' for code 70 (customer not on file) or 'Error Adding Motor Policy' for any other code.
  • REQ-F-021 When option '3' is entered on the motor policy screen, the system shall delete the motor policy (request 01DMOT to LGDPOL01) for the entered customer and policy number.
  • REQ-F-022 When the motor policy delete succeeds, the system shall show 'Motor Policy Deleted' with the dates, make, model, value, registration, colour, CC and manufacture date blanked, leaving premium, accident count and the option not cleared.
  • REQ-F-023 If the motor policy delete returns a non-zero code, then the system shall roll back the unit of work and show 'Error Deleting Motor Policy'.
  • REQ-F-024 When option '4' is entered on the motor policy screen, the system shall first display the current motor policy (request 01IMOT) and wait for the user to edit and resubmit it.
  • REQ-F-025 If the motor policy cannot be read for option '4', then the system shall show 'No data was returned.'.
  • REQ-F-026 When the user resubmits the edited motor policy, the system shall send the update (request 01UMOT to LGUPOL01) with the screen values and payment 0, broker id 0 and a blank broker reference, replacing any stored payment and broker details.
  • REQ-F-027 When the motor policy update succeeds, the system shall show 'Motor Policy Updated' and clear the option.
  • REQ-F-028 If the motor policy update returns a non-zero code, then the system shall show 'Error Updating Motor Policy' without a rollback.

J04 Manage a life (endowment) policy

Policy administrator · Look up, add, change or delete a customer's endowment policy so that their life cover is recorded correctly.

  1. General Insurance Endowment Policy Menu SSMAPP2: Start the endowment policy transaction (SSP2) to open the endowment policy screen; press CLEAR to start again with an empty screen if needed
  2. General Insurance Endowment Policy Menu SSMAPP2: Enter the customer and policy numbers and choose option 1 (Inquire) to see dates, fund, term, sum assured, life assured and fund choices, or see 'No data was returned.'
  3. General Insurance Endowment Policy Menu SSMAPP2: To add a policy, enter the customer number, dates, fund, term, sum assured, life assured and fund choices, choose option 2, and note the new policy number shown with 'New Life Policy Inserted' (or the add error)
  4. General Insurance Endowment Policy Menu SSMAPP2: To change a policy, choose option 4 to show its current details, edit them and press Enter; read 'Life Policy Updated' or 'Error Updating Life Policy'
  5. General Insurance Endowment Policy Menu SSMAPP2: To remove a policy, enter the customer and policy numbers and choose option 3
  6. General Insurance Endowment Policy Menu SSMAPP2: After an error, read the message on the cleared screen and enter again; if the option is not valid, correct it
  7. General Insurance Endowment Policy Menu SSMAPP2: Press PF3 to end the transaction
1 capabilities, 16 requirements
  • Endowment (life) policy inquire, add, delete and update rec/unassigned#3
  • REQ-F-029 The system shall treat endowment policy screen option '1' as inquire (LGIPOL01), '2' as add (LGAPOL01), '3' as delete (LGDPOL01) and '4' as inquire-then-update (LGIPOL01 then LGUPOL01).
  • REQ-F-030 If the operator presses Enter on the endowment policy screen with an option other than '1', '2', '3' or '4', then the system shall call no back-end program, show 'Please enter a valid option' with the cursor on the option field, and wait for the next input under transaction SSP2.
  • REQ-F-031 When the operator presses PF3 on the endowment policy screen, the system shall end the transaction with 'Transaction ended'.
  • REQ-F-032 When the operator presses CLEAR on the endowment policy screen, the system shall redisplay an empty endowment screen and continue under transaction SSP2.
  • REQ-F-033 When the operator chooses option '1' with a customer number and policy number, the system shall look up the policy (request '01IEND') and, on success, show its issue date, expiry date, fund name, term, sum assured, life assured, with-profits, managed fund and equities.
  • REQ-F-034 If the endowment policy inquiry returns a non-zero code, then the system shall show 'No data was returned.' and clear the screen and conversation data.
  • REQ-F-035 When the operator chooses option '2', the system shall send the customer number, issue and expiry dates, fund name, term, sum assured, life assured, with-profits, managed fund and equities for a new policy (request '01AEND'), with payment 0, broker 0 and a blank broker reference.
  • REQ-F-036 When adding the endowment policy succeeds, the system shall show the customer number, the newly assigned policy number and the fund name, clear the option field and show 'New Life Policy Inserted'.
  • REQ-F-037 If adding the endowment policy returns a non-zero code, then the system shall roll back the unit of work and take the add-error path.
  • REQ-F-038 If adding an endowment policy fails because the customer is not on file (return code 70), then the system shall roll back the unit of work, redisplay the endowment screen and clear the screen and conversation data for the next attempt.
  • REQ-F-039 If adding an endowment policy fails, then the system shall put the message 'Customer does not exist' (return code 70) or 'Error Adding Life Policy' (any other code) in the message field of the motor policy screen (ERP1FLDO), so the message does not appear on the endowment screen.
  • REQ-F-040 When the operator chooses option '4', the system shall first show the current policy details (request '01IEND'), wait for the operator to change them and press Enter, then send the changed details for update (request '01UEND') with payment 0, broker 0 and a blank broker reference, whatever values the policy held before.
  • REQ-F-041 If the first inquiry for option '4' fails, then the system shall show 'No data was returned.'.
  • REQ-F-042 When the endowment policy update succeeds, the system shall show the customer and policy numbers, clear the option field and show 'Life Policy Updated'.
  • REQ-F-043 If the endowment policy update returns a non-zero code, then the system shall show 'Error Updating Life Policy' and clear the screen and conversation data, without issuing a rollback.
  • REQ-F-044 If an inquiry, add, delete or update of an endowment policy fails, then the system shall redisplay the screen with the error message, then clear the screen data and conversation data and wait for the next input under transaction SSP2.

J05 Manage a house policy

Policy administrator · Add, change or delete a customer's house policy so that their property cover is recorded correctly.

  1. General Insurance House Policy Menu SSMAPP3: Start the house policy transaction (SSP3) to open the house policy screen
  2. General Insurance House Policy Menu SSMAPP3: To add a policy, enter the customer number, dates, property type, bedrooms, value, house name, number and postcode, choose option 2, and note the new policy number shown with 'New House Policy Inserted'; if the add fails, the screen is reset
  3. General Insurance House Policy Menu SSMAPP3: To change a policy, enter the customer and policy numbers, choose option 4 to show the current details (or 'No data was returned.'), edit them and press Enter; read 'House Policy Updated' or 'Error Updating House Policy'
  4. General Insurance House Policy Menu SSMAPP3: To remove a policy, enter the customer and policy numbers, choose option 3, and read the delete confirmation or 'Error Deleting House Policy'
1 capabilities, 9 requirements
  • House policy add, delete and update rec/unassigned#4
  • REQ-F-045 When option '2' is entered on the house policy screen, the system shall add a house policy (request 01AHOU to LGAPOL01) from the entered customer number, dates, property type, bedrooms, value, house name, house number and postcode, with payment 0, broker id 0 and a blank broker reference.
  • REQ-F-046 When the house policy add succeeds, the system shall show the customer number, the newly assigned policy number and 'New House Policy Inserted', and clear the option.
  • REQ-F-047 If the house policy add returns a non-zero code, then the system shall roll back the unit of work and reset the screen, without the intended message 'Customer does not exist' (code 70) or 'Error Adding House Policy' being shown on the house screen.
  • REQ-F-048 When option '3' is entered on the house policy screen (transaction SSP3), the system shall delete the house policy (request 01DHOU to LGDPOL01) and on success blank the dates and property details, clear the option and show 'House Policy Deleted'.
  • REQ-F-049 If the house policy delete returns a non-zero code, then the system shall roll back the unit of work, show 'Error Deleting House Policy' and reset the screen and request data.
  • REQ-F-050 When option '4' is entered on the house policy screen, the system shall first display the current house policy (request 01IHOU), then send the edited values as an update (request 01UHOU to LGUPOL01) with payment 0, broker id 0 and a blank broker reference, whatever values the policy held before.
  • REQ-F-051 If the current house policy cannot be read for option '4', then the system shall show 'No data was returned.'.
  • REQ-F-052 When the house policy update succeeds, the system shall show 'House Policy Updated' and clear the option.
  • REQ-F-053 If the house policy update returns a non-zero code, then the system shall show 'Error Updating House Policy' and reset the screen, without a rollback.

J06 Find, add or delete a commercial property policy

Policy administrator · Find commercial property policies by customer, policy number or postcode, and add or delete them so that commercial cover, perils and premiums are recorded correctly.

  1. General Insurance Commercial Policy Menu SSMAPP4: Start the commercial policy transaction (SSP4) to open an empty commercial policy form; press CLEAR to empty it again
  2. General Insurance Commercial Policy Menu SSMAPP4: Choose option 1 and enter a customer number, a policy number, both, or only a postcode to find the policy and see its address, location, perils, premiums and status, or see 'No data was returned.'
  3. General Insurance Commercial Policy Menu SSMAPP4: To add a policy, enter the customer number, dates, address, postcode, location, customer name, property type, perils, premiums, status and reject reason, choose option 2, and note the new policy number shown with 'New Commercial Policy Inserted' (or read 'Customer does not exist' or 'Error Adding Commercial Policy')
  4. General Insurance Commercial Policy Menu SSMAPP4: To remove a policy, enter the customer and policy numbers, choose option 3, and read the delete confirmation or 'Error Deleting Commercial Policy'
  5. General Insurance Commercial Policy Menu SSMAPP4: If the option is not valid, correct it and press Enter again
  6. General Insurance Commercial Policy Menu SSMAPP4: Press PF3 to end the transaction
1 capabilities, 17 requirements
  • Commercial property policy inquire, add and delete rec/unassigned#5
  • REQ-F-054 When the commercial policy transaction starts with no prior conversation data, the system shall show a fresh form with customer and policy numbers '0000000000' and empty peril, premium and status fields.
  • REQ-F-055 If the user enters any option other than '1', '2' or '3' on the Commercial Policy menu, including a blank option, then the system shall show 'Please enter a valid option', put the cursor on the option field, and call no back-end service.
  • REQ-F-056 When option '1' is entered with both a customer number and a policy number (neither blank nor zero), the system shall ask the policy inquiry service (LGIPOL01) for that customer's policy using request type '01ICOM'.
  • REQ-F-057 When option '1' is entered with a policy number but no customer number, the system shall search by policy number using request type '02ICOM'.
  • REQ-F-058 When option '1' is entered with a customer number but no policy number, the system shall search by customer number using request type '03ICOM'.
  • REQ-F-059 When option '1' is entered with neither a customer number nor a policy number but with a postcode, the system shall search by postcode using request type '05ICOM'.
  • REQ-F-060 When the policy inquiry succeeds, the system shall show the policy number, customer number, issue and expiry dates, address, postcode, latitude, longitude, customer name, property type, the fire, crime, flood and weather peril and premium values, status and reject reason.
  • REQ-F-061 If the policy inquiry service returns a non-zero code, then the system shall show 'No data was returned.' and clear the screen data for the next entry.
  • REQ-F-062 When option '2' is entered, the system shall send the customer number, issue and expiry dates, address, postcode, latitude, longitude, customer name, property type, peril and premium values, status and reject reason to the add-policy service (LGAPOL01) as request '01ACOM'.
  • REQ-F-063 When the add-policy service returns code 0, the system shall show the customer number and the newly assigned policy number, clear the option field and show 'New Commercial Policy Inserted'.
  • REQ-F-064 If the add-policy service returns a non-zero code, then the system shall roll back the work and show 'Customer does not exist' if the code is 70, or 'Error Adding Commercial Policy' for any other code.
  • REQ-F-065 When option '3' is entered, the system shall ask the delete-policy service (LGDPOL01) to delete the given customer's policy using request '01DCOM'.
  • REQ-F-066 When the commercial policy delete succeeds (code 0), the system shall blank the expiry date, address, postcode, latitude, longitude, customer name, property type, peril and premium values, status and reject reason, clear the option field and show 'Commercial Policy Deleted'.
  • REQ-F-067 If the delete-policy service returns a code above 0, then the system shall roll back the work and show 'Error Deleting Commercial Policy'.
  • REQ-N-001 When an option has been processed, the system shall return control so the next Enter continues under transaction 'SSP4'.
  • REQ-F-068 When the user presses PF3, or the commercial policy screen is received with no data, the system shall show 'Transaction ended' and end the session.
  • REQ-F-069 When the user presses Clear on the commercial policy screen, the system shall redisplay an empty form and continue under 'SSP4'.
