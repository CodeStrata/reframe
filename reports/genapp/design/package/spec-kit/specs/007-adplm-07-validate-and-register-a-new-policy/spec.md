# Feature specification: Validate and register a new policy

**Feature:** ADPLM-C07 · Application Deployment and Policy Lifecycle Management · Application Deployment Lifecycle Management

**Status: DRAFT**: the function is not signed off yet. Confirm with the owner before building to it.

## User scenarios and testing

### User story (ADPLM-C07)

As a policy administrator, I want an add-policy request checked, recorded as a master policy and given a policy number, so that only complete requests for known products and existing customers create policies.

Checks an add-policy request, records it as a master policy with a database-assigned policy number, and returns that number and the last-changed timestamp to the caller. It is for policy administrators. It must never create a policy for an unknown request type, for a request too short for its product, or for a customer who does not exist, and each of these failures must return its own code ('99', '98', '70').

**Acceptance scenarios:**

1. **Given** customer number: 0000000001; request ID: '01AEND', **when** policy add service runs, **then** Return code starts as '00' and customer 1 is used for the new policy row. (ADPLM-C07-AC-01)
2. **Given** request: '01AMOT'; request length: 150 bytes, **when** an add-policy request is shorter than the 28-byte header plus the full detail length for its type (Endowment '01AEND' 124, House '01AHOU' 130, Motor '01AMOT' 137, Commercial '01ACOM' 1174), **then** Return code '98' (Motor needs 165 bytes); no policy is inserted. (ADPLM-C07-AC-02)
3. **Given** request: '01ACOM'; request length: 1202 bytes, **when** an add-policy request is shorter than the 28-byte header plus the full detail length for its type (Endowment '01AEND' 124, House '01AHOU' 130, Motor '01AMOT' 137, Commercial '01ACOM' 1174), **then** Length check passes (Commercial needs 1202 bytes); the policy is added. (ADPLM-C07-AC-03)
4. **Given** request ID: '01AMOT'; request length: 150, **when** an add-policy request is shorter than the 28-character header plus the full record length for its type (124 endowment, 130 house, 137 motor, 1174 commercial), **then** Return code '98'; no policy is created (165 is required for motor). (ADPLM-C07-AC-04)
5. **Given** request ID: '01AHOU'; request length: 158, **when** an add-policy request is shorter than the 28-character header plus the full record length for its type (124 endowment, 130 house, 137 motor, 1174 commercial), **then** The length check passes and processing continues. (ADPLM-C07-AC-05)
6. **Given** request ID: '01AMOT', **when** an add-policy request has request ID '01AEND', '01AHOU', '01AMOT' or '01ACOM', **then** The policy is recorded with type 'M' (motor). (ADPLM-C07-AC-06)
7. **Given** request ID: '01ACOM', **when** an add-policy request has request ID '01AEND', '01AHOU', '01AMOT' or '01ACOM', **then** The policy is recorded with type 'C' (commercial). (ADPLM-C07-AC-07)
8. **Given** request: '01AHOU'; customer number: 1000001; issue date: 2026-01-01; expiry date: 2027-01-01; broker ID: 55; payment: 300, **when** a recognised add-policy request ('01AEND', '01AHOU', '01AMOT' or '01ACOM') passes the length check, **then** A policy row is stored with a new number (e.g. 2000123), type 'H', last-changed = the current timestamp, broker 55 and payment 300. (ADPLM-C07-AC-08)
9. **Given** request: '01AMOT'; customer number: 1000002, **when** a recognised add-policy request ('01AEND', '01AHOU', '01AMOT' or '01ACOM') passes the length check, **then** A policy row is stored with type 'M' and a database-assigned number. (ADPLM-C07-AC-09)
10. **Given** request identifier: '01AMOT', **when** an add-policy request with request identifier '01AEND', '01AHOU', '01AMOT' or '01ACOM' has passed the length check, **then** A POLICY row of type 'M' is inserted, then a MOTOR row with the new policy number. (ADPLM-C07-AC-10)
11. **Given** request identifier: '01AHOU', **when** an add-policy request with request identifier '01AEND', '01AHOU', '01AMOT' or '01ACOM' has passed the length check, **then** A POLICY row of type 'H' is inserted, then a HOUSE row with the new policy number. (ADPLM-C07-AC-11)
12. **Given** request identifier: '01ACOM', **when** an add-policy request with request identifier '01AEND', '01AHOU', '01AMOT' or '01ACOM' has passed the length check, **then** A POLICY row of type 'C' is inserted, then a COMMERCIAL row with the new policy number. (ADPLM-C07-AC-12)
13. **Given** request ID: '01AHOU', **when** a recognised add-policy request passes the length check, **then** A POLICY row is inserted, then a HOUSE row for the new policy number, then LGAPVS01 is called. (ADPLM-C07-AC-13)
14. **Given** policy insert: succeeds, number 2000123 assigned, **when** the policy row is inserted successfully, **then** Return code '00'; the caller receives policy number 2000123 and the stored last-changed timestamp, e.g. 2026-11-25-10.15.30.000000. (ADPLM-C07-AC-14)
15. **Given** customer number: 9999999 (not on file), **when** the new policy row is rejected because the customer number is not on the customer table (SQL code -530), **then** Return code '70', error logged with CNUM=9999999, no policy or detail row stored. (ADPLM-C07-AC-15)
16. **Given** customer number: 9999999 (not on file); request: '01AHOU', **when** the database rejects the policy insert because a referenced record does not exist (SQLCODE -530, e.g. an unknown customer), **then** No policy is added; return code '70'; an error message is logged. (ADPLM-C07-AC-16)
17. **Given** policy insert: fails with a database error other than -530, **when** the new policy row cannot be stored for any other reason, **then** Return code '90', error logged, nothing further stored. (ADPLM-C07-AC-17)
18. **Given** policy insert: fails with SQLCODE -911, **when** the policy insert fails for any other reason, **then** No policy is added; return code '90'; an error message is logged. (ADPLM-C07-AC-18)
19. **Given** CA-REQUEST-ID: '01AMOT'; CA-CUSTOMER-NUM: 1000042; Policy and motor inserts: succeed, **when** policy registration processing completes without ending early, **then** LGAPDB01 LINKs to 'LGAPVS01' with the full request data, length 32500 (ADPLM-C07-AC-19)
20. **Given** An add-policy request with request ID '01XHOU' (not one of '01AEND', '01AHOU', '01AMOT' or '01ACOM') for an existing customer, and the policy table is in a known state, **when** The policy add service processes the request, **then** Return code '99' is returned to the caller at once, no new row is added to the policy table, and no endowment, house, motor or commercial row is added (ADPLM-C07-AC-20)
21. **Given** An add-policy request with request ID '01IEND', an inquiry code rather than one of the four add codes, that is long enough for an endowment add, **when** The policy add service processes the request, **then** Return code '99' is returned and no policy is created (ADPLM-C07-AC-21)

## Requirements

### Functional requirements

- **ADPLM-REQ-F-037** (design note): The system shall start each add-policy request with return code '00' and keep the request's customer number for the database insert and for any error message. Rules: ADPLM-BR-038.
- **ADPLM-REQ-F-038** (business rule): If an add-policy request has any request ID other than '01AEND', '01AHOU', '01AMOT' or '01ACOM', then the system shall return code '99' to the caller at once, without creating any policy. Rules: ADPLM-BR-039.
- **ADPLM-REQ-F-039** (business rule): If an add-policy request is shorter than the 28-byte header plus the full detail length for its type (Endowment '01AEND' 124, House '01AHOU' 130, Motor '01AMOT' 137, Commercial '01ACOM' 1174), then the system shall return code '98' to the caller and record nothing. Rules: ADPLM-BR-040, ADPLM-BR-041.
- **ADPLM-REQ-F-040** (business rule): When an add-policy request has request ID '01AEND', '01AHOU', '01AMOT' or '01ACOM', the system shall record the new policy's type as 'E' (endowment), 'H' (house), 'M' (motor) or 'C' (commercial) respectively. Rules: ADPLM-BR-042.
- **ADPLM-REQ-F-041** (business rule): When a recognised add-policy request ('01AEND', '01AHOU', '01AMOT' or '01ACOM') passes the length check, the system shall insert a policy row holding a database-assigned policy number, the customer number, issue and expiry dates, the policy type ('E', 'H', 'M' or 'C'), the current timestamp as last-changed, broker ID, broker's reference and payment. Rules: ADPLM-BR-043.
- **ADPLM-REQ-F-042** (business rule): When a recognised add-policy request passes the length check, the system shall first record the policy in the main policy table and then record the endowment, house, motor or commercial details that match the request identifier. Rules: ADPLM-BR-044, ADPLM-BR-045.
- **ADPLM-REQ-F-043** (business rule): When the policy row is inserted successfully, the system shall set return code '00' and return to the caller the assigned policy number and the last-changed timestamp read back from the stored policy row. Rules: ADPLM-BR-046.
- **ADPLM-REQ-F-044** (business rule): If the new policy row is rejected because the customer number is not on the customer table (SQL code -530), then the system shall set return code '70', log the error with the customer number, and return to the caller without storing any type-specific details. Rules: ADPLM-BR-047, ADPLM-BR-048.
- **ADPLM-REQ-F-045** (error handling): If the new policy row cannot be stored for any other reason, then the system shall set return code '90', log the error, and return to the caller without storing any type-specific details. Rules: ADPLM-BR-049, ADPLM-BR-050.
- **ADPLM-REQ-F-046** (business rule): When policy registration processing completes without ending early, the system shall pass the full request data, length 32500, on to the follow-on program LGAPVS01. Rules: ADPLM-BR-051, ADPLM-BR-045.

### Needs clarification

- SME-030: When an add-policy request arrives with no request data at all, what should happen: should it be rejected with a specific code, or should processing just stop? (Policy administration business analyst) On ADPLM-BR-040, ADPLM-BR-042, ADPLM-BR-039.
- SME-031: When saving a new policy fails for a reason other than the customer not existing, what outcome code should the caller get back? (Policy administration business analyst) On ADPLM-BR-044, ADPLM-BR-045, ADPLM-BR-047, ADPLM-BR-049, ADPLM-BR-043, ADPLM-BR-046, ADPLM-BR-050.
- SME-032: What format (data type and length) should the policy number have when the policy data store assigns it? (Data architecture team) On ADPLM-BR-044, ADPLM-BR-045, ADPLM-BR-047, ADPLM-BR-049, ADPLM-BR-043, ADPLM-BR-046, ADPLM-BR-050.
- SME-034: When adding a policy is rejected for a bad reference, does that always mean the customer does not exist, or can it also mean the broker is unknown? Should an unknown broker be reported differently? (Data architect / DBA) On ADPLM-BR-047.
- SME-037: After a policy is added, it is passed on to a follow-on step (LGAPVS01). What does that step do for the business, for example keeping a file copy or an audit record? Should the whole add fail if that step fails? (Policy administration SME) On ADPLM-BR-051.
- SME-038: The name of the person whose life is assured on an endowment policy is supplied as 31 characters but stored in 30. Is it intended that the 31st character is dropped? (Policy administration business analyst) On ADPLM-BR-051.
- SME-039: New policies are recorded in two places, the policy database and a separate policy file. Does the new system need to keep both, and if so, which one is the official record? (Data architecture team) On ADPLM-BR-051.
- DEF-005: Is this intended? LGAPOL01, the only caller in the source, always links with a length of 32500, so this check can never fail on that path; it guards only callers that pass the true length. (Subject-matter expert) On ADPLM-BR-040.
- DEF-006: Is this intended? The length check can never fail when the request comes through LGAPOL01, because LGAPOL01 always links to LGAPDB01 with a fixed length of 32500, so a short request is not caught here. The second 'request not recognised' branch at detail routing is also dead code, since unknown request IDs have already been returned with '99'. (Subject-matter expert) On ADPLM-BR-042, ADPLM-BR-039, ADPLM-BR-045.
- DEF-012: Is this intended? After a successful insert, neither the IDENTITY_VAL_LOCAL() call nor the read-back of LASTCHANGED is checked for an SQL error, so a failed read-back would still return '00' with a blank or stale timestamp. (Subject-matter expert) On ADPLM-BR-043, ADPLM-BR-046, ADPLM-BR-050.
