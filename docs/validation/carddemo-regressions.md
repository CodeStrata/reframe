# CardDemo regression inventory (spec §10)

Each failure seen in the saved CardDemo run has at least one offline test that reproduces it. These tests check the behavior, not CardDemo business answers. The password, customer-key, GDG, and transaction contradictions stay unresolved evidence, and no test settles them.

`tests/test_regression_index.py` reads this table and fails if a named test no longer exists.

**Fixtures.** Most tests build small synthetic workspaces. Two kinds go further:

- **Scale.** `tests/carddemo_scale.py` generates a sanitized specification at saved CardDemo size: 452 SME questions, 54 saved deferrals, and a legacy wireframe request over 600 000 bytes. All of its text comes from a fixed word list, so it runs on any machine.
- **Saved workspace (read-only).** Tests marked *saved* also read the saved CardDemo workspace when it is on the machine. They never write to it, and they skip when it is absent. Each such item also has a synthetic test that runs everywhere.

## Near-threshold checks (NR-03)

`tests/test_carddemo_scale.py` sizes a single record to the exact staged byte budget. That record fits in one stage. One more byte is refused with both sizes named, and nothing is truncated. Through the CLI, the refused request leaves `ui_calls`, the preparation call count, and the preview folders unchanged. With the design plan included in the request, every stage still fits.
